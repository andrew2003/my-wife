# Contributing

Read `CLAUDE.md` first. It holds the language policy, product principles, engineering conventions
and the resource budget. Everything in the repository is written in English; user-facing text lives
in the `vi` and `en` locale files.

## Workflow

1. Pick an issue. Read it, the spec file it points to, and the matching part of `packages/contracts`.
2. Branch from `main`: `<type>/<issue-number>-<short-kebab-summary>`, for example
   `feat/42-coded-transfer-matching`.
3. Write tests for each acceptance criterion first and see them fail. Then write the code.
4. Run package-scoped checks: `pnpm --filter <package> lint`, `typecheck`, `test`.
5. Open one small PR per issue. State what changed, why, and how to verify. Link the issue.

Never delete, skip or weaken a test to get a green run. Changes to `packages/contracts` or CI
workflows need an ADR.

## Commits and pull requests

Commits follow [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/):

```
<type>(<scope>): <subject>
```

- Types: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`, `revert`.
- Scope: one of the list in `commitlint.config.mjs` (services, packages, `infra`, `e2e`, ...).
- Subject: imperative, lowercase first letter, no trailing period, at most 72 characters.
- A breaking change adds `!` after the scope and a `BREAKING CHANGE:` footer.

A `commit-msg` hook (husky and commitlint) checks every commit locally. CI checks every commit of a
PR and the PR title, because the squash merge turns the title into the commit on `main`.

`main` is protected: PRs only, green CI, squash merge only, linear history, no force push. Versions
and `CHANGELOG.md` are generated by release-please from the commit history.

## Formatting and linting

ESLint (flat config at the root) and Prettier are the formatting authority. Run `pnpm format` and do
not hand-format against them. `.editorconfig` covers editors.

## Secrets

Never commit secrets, `.env` files (only `.env.example`), or anything under the local `factory`
state. Secret scanning and push protection are enabled on the repository.
